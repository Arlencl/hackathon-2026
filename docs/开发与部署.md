# 开发与部署

维护日期：2026-10-12。GitHub 是源码和文档交付入口，Sites 托管公开体验；两者的更新是独立操作。

## 从 GitHub 运行

准备 Node.js 与 pnpm。本机已验证 Node.js 24.19.0；使用仓库锁文件安装依赖，不必重新生成图片或世界模型。

```sh
git clone https://github.com/Arlencl/hackathon-2026.git
cd hackathon-2026
pnpm install --frozen-lockfile
pnpm run build
pnpm test
pnpm start
```

打开 [景区地图](http://127.0.0.1:4173/#map) 或 [御碑亭试点](http://127.0.0.1:4173/#pilot)。服务只监听 `127.0.0.1:4173`，Ctrl+C 停止。

`pnpm dev` 与 `pnpm start` 当前都执行 `node server.mjs`，没有热更新。修改 `src/` 或素材后，需要重新构建并刷新。从 Git 克隆没有 `dist/`，直接启动服务会出现文件未找到。

Mac 启动文件会尝试系统 Node 或本机已有的 Codex 运行时，不能替代首次依赖安装和构建。其他系统可在构建后执行 `node server.mjs`。完全离线演示需要预先安装、构建并保留全部静态资产；外部来源链接和真实 API 仍需要网络。

## 可选服务配置

只观看已有照片、地图、SPZ 和模拟工作流不需要配置密钥。

```sh
cp .env.example .env
```

| 变量 | 用途 |
| --- | --- |
| `WORLDLABS_API_KEY` | 本机高级工作台的真实世界模型请求 |
| `WORLDLABS_MODEL` | 默认 `marble-1.1` |
| `LLM_BASE_URL` | 兼容服务的基础 URL；代码追加 `/chat/completions` |
| `LLM_API_KEY`、`LLM_MODEL` | 可选资料问答模型 |
| `PORT` | 默认 `4173` |
| `JINGJIAN_DATA_DIR` | 可选本机任务与快照存储目录，默认仓库下 `data/` |

填入 `.env` 后重启 Node 服务，访问 `/api/health` 查看配置状态。真实生成入口位于 `/#legacy-studio`；`/#studio` 的模拟任务不会因为填入密钥而自动变成真实生成。

密钥仅由服务端读取。不要提交 `.env`、签名上传 URL、账户响应或用户上传资料；忽略规则见 [.gitignore](../.gitignore)。API 请求超时不代表服务商没有创建任务，先核对平台记录和本机任务状态。

## 图片与构建产物

`public/` 保存原始素材、网页副本和模型。普通构建直接使用已提交副本，因此 Linux、Windows 不需要 macOS 图片工具。

当维护者替换原始图片时，可在 macOS 运行：

```sh
node scripts/prepare-web-images.mjs
pnpm run build
```

脚本使用 `sips` 输出最长边 1920 px、JPEG 质量 85 的网页副本，保留原文件。副本与 [manifest.json](../public/assets/web/manifest.json) 一起提交。构建验证双方 SHA-256，发现不匹配会报 `Web image is stale`，避免悄悄使用旧副本。

运行时仅映射内置素材地址，用户上传图片与外部 URL 不被改写。原始御碑亭生成输入、两份 SPZ 随网站发布；未使用的全景原图和其他已提供副本的高清文件保留在 Git，按构建规则排除出部署包。

`dist/` 是构建输出，`data/` 是本机数据，`artifacts/` 是本机打包和验收产物；这些目录不提交。

## 公开部署

当前公开地址：[景见](https://jingjian-westlake-2026.raremint.chatgpt.site/#map)。最近成功发布为 Sites 第 4 版，2026-10-12；部署源提交为 `3ba034929117ec436a93ea620f36249be72a4b22`。

仓库 [.openai/hosting.json](../.openai/hosting.json) 绑定已有 Sites 项目，静态目录是 `dist`。维护现有网站时保留项目 ID、域名和公开访问设置。

完整顺序：

1. 完成源码修改、相应测试和页面验证。
2. 构建 `dist/`，检查网页副本、SPZ 和生成记录齐全。
3. 使用 Sites 的 source workflow 同步同一份源码并生成部署压缩包；源码提交与包内容必须一致。
4. 保存网站版本，再发布该版本；保存成功不等于已经上线。
5. 等待部署状态为 `succeeded`，再验证实际公开地址与核心入口。

使用 Codex Sites 插件时，按照当前安装的 Sites 技能与 source helper 操作；短期凭据只通过内存和标准输入传递。普通 GitHub 推送不会自动部署本站，仓库目前没有 GitHub Actions 发布流水线。只维护 README 或文档时，无需重新发布静态网站。

两个 Git 镜像的历史与 Sites 源仓库历史不同。维护脚本同步同一源码树，不强推覆盖历史；不要把部署源提交 ID 当成 GitHub 镜像提交 ID。

## 本次上传超时记录

旧部署包约 16 MB。加入真实景点照片、五张补图和额外全景图后，新包约 70 MB，上传多次在约 60 秒后超时，尚未进入部署阶段。

排查时上传服务器可连接；将网页素材改为压缩副本、排除未使用全景原图后，包降至约 31 MB，同一网站成功保存并部署第 4 版。这个结果支持大包体积是重要影响因素；60 秒是本次上传工具出现的超时，不应写成 Sites 对所有网站的固定容量上限。

后续遇到相同问题先检查包大小和内容，保留原素材，避免反复重传未优化的大文件。源码推送成功、部署包上传成功、网站上线成功应分别核验。

## 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 本地网页打不开 | 确认 Node 服务正在运行及端口正确；`127.0.0.1` 只指当前设备 |
| 启动后显示文件未找到 | 先安装依赖并运行构建；服务读取的是 `dist/` |
| 改代码后没有变化 | 重新构建并刷新；该服务不自动编译 |
| 仍看到旧湖景 | `/#world` 是旧场景，御碑亭入口是 `/#pilot` |
| 没有背面、俯视 | 检查 `/#studio` 的草稿是否补齐并接受，再发布到本机预览；旧发布快照不会被强制覆盖 |
| 景点详情没有三维入口 | 目前只有保留内置原始正面实拍的御碑亭绑定试点；其他景点是照片预览 |
| 换电脑后上传内容消失 | 新素材仅存在原浏览器；公开站点并没有收到本机草稿 |
| 公开站点不能真实调用模型 | 云端只部署静态前端；可选 Node API 在本机 |
| 模型离开起点后失真或穿透 | 这是生成资产和自由相机的已知边界；重置返回起点，不代表路径可通行 |
| 新备份无法导入旧工作台 | 两种工作流格式不同；新备份恢复 UI 尚未实现 |

涉及本机内容的排查先导出备份，不以清空存储作为默认修复方式。

## 验收与文档维护

`pnpm test` 使用 Node 原生 test runner；构建同时校验网页图片哈希。新功能需验证游客与维护端分工、草稿隔离、AI 图片审核和实际模型入口。

[旧浏览器脚本](../scripts/browser-qa.mjs) 依赖额外的 Playwright/Chrome 环境并面向早期页面，不包含在默认依赖中。脚本仍使用旧 `/#studio` 定位，需适配现在的路由后才能用于回归，也不覆盖全部新工作流。新地图、六视角和御碑亭需要单独进行浏览器交互验收。

每次影响体验的变更同时更新 [产品文档](产品与景区工作流.md)、[演示脚本](比赛与演示.md) 和 [更新记录](../CHANGELOG.md)。报告测试时注明实际运行范围，报告上线时只记录部署成功的版本。
