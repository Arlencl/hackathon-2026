# 一周参赛计划与演示脚本

当前定位：以一个可运行作品验证景区伙伴能否维护沉浸式双语体验。名称暂定「景见」，不把赛道写进名称。

## 报名文案

项目名称：景见（暂定）

赛道建议：P｜伙伴。依据此前对话中提供的赛道含义拟定；报名之前仍需对照正式比赛通知核实限制、提交物与评分标准。

赛题规划：面向景区伙伴，探索把图片和讲解资料转化为可交互的景点预览与双语数字导览，并提供内容导入、编辑、核验、发布和更新工具。以西湖文化景观为概念试点，打通伙伴维护内容、游客进入场景和按点位问答的闭环；世界模型生成通过独立服务接入，游客讲解依据发布资料并保留来源，降低伙伴共建多语言体验的操作门槛。

创新表达：空间点位与讲解共用上下文；伙伴持续维护可信资料；发布快照把草稿审核与游客体验连接起来。世界模型承担视觉生成，结构化资料承担事实依据。

## 五分钟现场演示

**0:00–0:35，建立问题。**

“景区已经有照片、也有讲解稿，但游客很难从几张图片里读懂空间，更难跨过语言理解文化。我们想把这些材料变成一段能探索、能提问、也能被景区持续维护的体验。”

首页进入 `/#world`，拖动环顾、向前移动，打开「生成记录」。说明这是 Marble 1.1 从 AI 概念图生成的三维资产，不是实景数字孪生。

**0:35–1:25，证明场景与讲解联动。**

点「临水小亭」，镜头聚焦，问「讲讲眼前的风景」。展开 UNESCO 与演示策展来源。切 EN，展示英文讲解，说明表达面向海外游客。

**1:25–1:55，展示可信边界。**

问「今天几点开放？」。初始内容应回答没有核实。说明模型画出一扇门，不代表知道门何时开放。资料和视觉各司其职。

**1:55–3:25，展示伙伴能力。**

点「工作流演示」进入 `/#tour`，再到工作台 → 讲解审核 → 临水小亭。这个五点位场景用于验证内容发布，与生成样例分开维护。

- 中文运营提示：`演示通知：临水小亭将在 16:00 后暂停访问，请在其他点位继续预览。`
- 英文提示：`Demo notice: the pavilion closes after 16:00. Please continue your preview at another viewpoint.`

先点「保存草稿」。回游客端问运营提示，旧版本仍没有提示。再回工作台核验、发布。重新进入游客端再问，回答出现新提示。

不要把此演示通知当作真实景区公告。它是为了测试发布链路而输入的样例。

**3:25–4:10，展示可维护性。**

发布与版本 → 切回 v1，重复问题，证实回滚。展示图片、JSON 与文字导入，说明没有已核验英文的点位无法发布。

**4:10–5:00，讲工程与下一步。**

当前完成：真实 Marble 1.1 API 生成、SPZ 下载与自有网页播放、双语资料问答、导入/审核/发布/回滚。

待完成：真实景区素材重建试验、通用空间校准、语言模型联调和伙伴操作验收。近景仍可能变形，生成画面不作为历史或运营事实。

收尾：“我们希望景区获得的，是自己可以维护的数字体验。让游客看得见风景，也能理解风景。”

## 评委问答

**和全景照片有什么区别？** 本作品将可探索的三维资产与可维护的点位知识结合。生成入口播放实际 SPZ，支持视角旋转和空间移动；五点位工作流演示仍使用程序场景。

**和普通聊天机器人有什么区别？** 导游具有当前点位、当前语言和发布版本上下文，能回溯来源。没有资料时明确未知，运营修改必须经过审核发布。

**为什么是伙伴赛道？** 伙伴端有实际可操作的导入、双语编辑、核验、发布与回滚。游客体验是伙伴交付能力的结果。

**能降低多少成本？** 目前未获得真实测量。下一步比较同一资料下的人工双语整理与工具流程，记录完成时间、修改量和发布成功率。

**是不是写死的演示？** 可以现场改提示、发布、回滚、导入新资料和加载真实 splat。离线问答的检索机制是确定性的，界面有明确标注。真实模型调用需要配置对应密钥，并单独验证。
